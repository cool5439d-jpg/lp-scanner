# LP 选池扫描器

扫描 Robinhood 链上所有池子，筛出**当下适合做 LP** 的那些，并为每个池给出**保守、最佳、激进三档表单填法**，字段和 rh-uni 网页表单一一对应，可以直接照抄。

只看 Uniswap v4 加 USDG 计价的池，因为那是 rh-uni 唯一能建仓的组合。

## 用法

```bash
cd <本仓库目录>

python scan.py                                  # 只扫描排名
python scan.py --verify 3 --available 5000      # 扫描 + 终审 + 三档填法
python scan.py --watch --verify 3               # 观察模式
python scan.py --show-rejected                  # 看被淘汰的池和原因
```

`--available` 填你钱包里的可用 USDG，三档仓位据此计算。`--verify N` 对排名前 N 个池跑真实演练，每个约 15 秒。

数据源是 GeckoTerminal 和 GoPlus。所在网络直连不了的话，先设代理再运行：

```bash
export https_proxy=http://<你的代理地址>:<端口>
```

`--verify` 需要能调用到 rh-uni，路径在 `verify.py` 的 `TOOL_DIR`，默认是本仓库同级的 `robinhood-chain-LP`。

## 定时监控与桌面提示

最省事的方式是在网页里开：打开 `http://127.0.0.1:3200`，「定时监控」卡片里点「开启监控」，填好间隔、预算、可用资金即可。开关状态会落盘到 `watch_state.json`，服务重启后自动恢复上次的开或关，不会悄悄变成没开。卡片上能看到已跑轮数、发出的提示数、上次和下次扫描时间，旁边有「提示记录」和「测试通知」。

命令行方式仍然可用，适合不开网页的场景：

```bash
python watch.py --budget 500 --available 8700   # 每 15 分钟一轮，持续运行
python watch.py --test-notify                   # 只测通知
python watch.py --once                          # 只跑一轮
python watch.py --interval 1800                 # 改成 30 分钟
```

达标就弹 Windows 通知并播提示音，同时写入 `alerts.log`。用系统原生通知机制，不需要装任何模块。

**两级提示。** 机会提示只在决策卡判定为「投」时响，即七项体检无红灯且总分 12/14 以上。持仓预警在你的仓位出现两个以上撤退信号时响，持仓列表自动从 rh-uni 读取。

**同一个池只提示一次**，除非评分或信号数量发生变化。已提示记录 6 小时后过期。门槛刻意设得很严：门槛低了你会被无关提示淹没，然后开始忽略它们，那这套东西就白做了。

**为什么是 15 分钟而不是 5 分钟。** 一是接口限流，全量扫描要抓七页且页间强制间隔 5 秒，间隔太短会收到 429，数据不全反而误判。二是发现机会后你要演练、核对、执行，一轮至少五到十分钟，扫太快处理不完。三是再快也没有信息增益，资金流指标本身就是 5 分钟成交对比过去一小时。

## 单币查询

全量扫描按成交量翻七页，冷门币和刚建池的币根本不在榜上。网页的「单币查询」卡片专门补这个缺口：填代币地址或符号，把它在本链 Uniswap v4 上**全部 USDG 池**按扫描器同一套标准过一遍，通过的给出决策卡和三档填法，淘汰的列出原因。判定逻辑完全复用 `judge` / `plans` / `decide` / `advice`，不另起标准。

符号搜索走 GeckoTerminal 的搜索接口，同名多个代币时列出候选让你点选。勾上「跑演练终审」会对每个通过的池跑一次 rh-uni 的 `--dry-run`，每个约 15 秒。查完可以一键「加入监测器」。

## 代币监测器

和「定时监控」分工不同：定时监控每 15 分钟扫全链找新机会，监测器每 60 秒只看名单上的几个币，用来盯你**已经开了仓**的那些。全链扫描要抓七页、页间强制等 5 秒，做不到分钟级；单币接口一次一个请求，几个币一轮几秒就完。

每一轮对名单上每个币：抓它的全部池 → 挑出你持仓的那个池（没指定就取流动性最大的）→ 算资金流、阶段、撤退信号、时点 → 存一个样本。页面上每个币一张卡：现价和 5m/1h/6h/24h 涨跌、换手、流动性、5 分钟成交、阶段和资金流标签、价格折线（1 分钟一个点，保留一天）。持仓的币还会画出**区间条**：绿色带是你的区间，白线是现价，出区间变红，旁边是价值、已收手续费、盈亏，这些直接读 rh-uni 的 `/api/positions`。

两种弹窗：撤退信号到两个且数量变化时（复用 `notify.warnings` 的去重），以及仓位跳出区间时（每个仓位只提醒一次）。撤退信号两个卡片变黄，三个变红。

**持仓自动同步。** 监测器每轮开头读一次 rh-uni 的仓位，新开仓的币自动进名单并锁定仓位所在的池，不用手动导入。你从名单里手动移出的持仓币会被记住，自动同步不再加回；该币的仓位全部关掉后记录清除，下次再开仓又会自动进来。「导入 rh-uni 持仓」按钮保留，点它会强制把全部持仓加回，包括被移出过的。勾选框可以整体关掉自动同步。

名单、屏蔽记录和最近一天的样本落盘到 `monitor.json`，服务重启自动恢复。抓取失败时沿用上次读数并在卡片上标红，不会把读数清零。

## 生命周期分段：现在该怎么摆流动性

做 LP 只有两个问题：价格接下来往哪走，你的流动性在不在它经过的路上。只有价格在你的区间里穿梭时才收得到手续费。所以脚本先判断这个币处在哪个阶段，再决定形状和区间。

| 阶段 | 形状 | 区间 | 仓位系数 | 理由 |
|---|---|---|---|---|
| 拉升 | bidask 三层 | 偏上方 | 0.8 | 价格往上走，流动性放上方才会被反复穿过 |
| 横盘 | spot 集中 | 对称 | 1.0 | 价格不跑远，集中则同样的来回收更多费 |
| 反弹 | curve 三层 | 对称偏宽 | 0.5 | 方向未定，别赌单边 |
| 见顶 | spot | 加宽 | 0.25 | 涨幅集中在过去，当下滞涨，随时回落 |
| 崩盘 | 不做 | 加宽 | 0 | 成交萎缩收不到费，单边跌会把 USDG 持续换成这个币 |

**判断阶段必须同时看价格和资金流。** 只看价格会把「拉升」和「反弹后见顶」混为一谈，只看资金流会把「横盘但成交活跃」误判成拉升。

另一个坑是**滚动窗口**。1 小时、6 小时这些指标都是拿现在和 N 小时前比。价格刚从底部拉起来时，这些窗口仍是深负，但当下已经在涨。CME 实测 5 分钟 +6.3% 而 1 小时 -27%，只看 1 小时就会把刚反弹的判成还在崩盘。所以 5 分钟涨超 2% 且 24 小时深跌时，优先判为反弹。

## 资金流：APR 是历史，5 分钟成交才是当下

仪表板上的 APR 是快照，不代表未来。一个池子的 5 分钟成交开始萎缩，手续费就在快速消失，而 APR 还会挂着漂亮数字。

做法是把 5 分钟成交换算成小时速率，和过去一小时的实际速率比：

| 比值 | 判定 | 含义 |
|---|---|---|
| ≥ 2.0 | 涌入 | 当下比过去一小时更热 |
| 0.6 ~ 2.0 | 正常 | 资金流稳定 |
| 0.3 ~ 0.6 | 退潮 | 成交在萎缩，手续费会跟着掉 |
| < 0.3 | 枯竭 | 一票否决，钱不流了留在池子里只剩风险 |

报告里还会列出**撤退信号**：成交萎缩、价格急跌、中期破位、交易稀疏。中两个减仓，中三个清仓。

## 三档方案怎么分

三档只在两处不同：投入多少、区间多宽。其余字段三档相同，因为那些是安全设置，不该拿来赌。

| | 仓位 | 区间（中波动为例） | 特点 |
|---|---|---|---|
| 保守 | 可用资金 25% | -40%,40% | 价格很难跑出去，省心，收益低 |
| 最佳 | 50% | -25%,25% | 收益与风险的平衡点 |
| 激进 | 80% | -15%,15% | 收益高，但要盯盘和频繁再平衡，gas 消耗大 |

区间宽度按波动率自动调整，低波动的币三档分别是 25/15/8，高波动是 60/35/22。

仓位有三道闸取最小：按可用资金比例、演练验证过的上限、池子流动性的千分之五。最后一道是硬约束，占比太高你自己就是撤退时把价格砸下去的人。

## 演练终审：为什么必须有

这是 HOOD 那次踩坑换来的，教训有两层。

第一层，**GeckoTerminal 报的流动性完全无法预测价格冲击**。HOOD 池报 22.7 万 TVL，和 AI 池同量级，但换 95 美元就把价格打掉 48%，AI 换 220 美元毫无冲击。因为集中流动性可以把钱全堆在远离现价的位置，账面很厚，现价这里空空如也。

第二层更隐蔽，**直接问链上 Quoter 也会被骗**。HOOD 的 v4 池自己报价只有 0.24% 冲击，看着完全没问题。但 rh-uni 换币走的是 Uniswap 路由接口，那条路径给出的是 -78%。真正的约束在换币这一步，不在池子深度。

所以唯一可靠的判据是跑一遍工具自己的 `--dry-run`。`--verify` 就是干这个，用的是和实际执行完全相同的代码路径。

## 三个关键指标

**日换手** 等于日成交除以流动性，是收入的根本来源，也最难被操纵。

**持久度** 等于实际 24 小时成交除以「1 小时成交乘 24」。100% 附近说明成交全天均匀，远低于说明全部挤在最近一小时。热榜上那些一小时涨幅惊人的币，持久度往往只有个位数。

**上榜率** 来自历史扫描，跑够三次才显示。偶尔冲榜不算什么，连续上榜才是真稳定。

## 淘汰规则

池子本身不合格：流动性低于 5 万撤退时卖不掉，高于 300 万小资金被稀释，日成交低于 20 万没人用，日笔数低于 1500 可能是刷量，日换手低于 2 倍赚不到钱。

时机不对：24 小时涨超 30% 是暴涨途中进场会在半山腰卖光，跌超 20% 且 6 小时仍在跌是接刀子，持久度低于 40% 是烟花。

所有阈值在 `config.py`，改那一个文件即可。

## 收益估算的准确度

用你 MEME 实盘反推校准过。实际年化约 2041%，脚本算出 1640%，同一量级。公式是池日手续费总额乘以你的出资占比，再乘一个集中系数。集中系数用了开方而不是线性，因为你的钱只占池子极小一部分，池内其他 LP 的分布才是主导。

**预估日入只算手续费，不含币价盈亏。** 报告里每个池都会提示按当前波动率本金一天可能变动多少，那个数字通常远大于手续费收入。这是做 LP 最容易被忽略的一点。

`quote_probe.mjs` 和 `depth.py` 是探索过程中的产物，已被 `verify.py` 取代，保留作参考。

## 它不回答什么

这个工具只判断「哪个池成交活跃、当下值不值得进、能吃下多少钱」，不预测币价。筛掉的是明显的坑，剩下的仍然要你自己决定愿不愿意承担那个币的价格风险。
